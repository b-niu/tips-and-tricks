# rsync：向非空目录增量合并

> **体例**：每个命令模块后紧跟一个参数解释表（短参 / 长参 / 释义），**只解释首次出现的参数**；后文再用到时直接引用。

## 30 秒上手

**主力命令**，本地把 `A/` 增量合并进 `B/`（把 `--remove-source-files` 换成 `--remove-empty-dirs --remove-source-files` 就是移动）：

```bash
rsync -rtlp --info=progress2 A/ B/
```

**动手前先看计划**，加 `-n` 不落盘、`-i` 逐条列出动作：

```bash
rsync -rtlpni --info=progress2 A/ B/
```

| 短参 | 长参 | 释义 |
|------|------|------|
| `-r` | `--recursive` | 递归子目录 |
| `-t` | `--times` | 保留文件 mtime。**必留**——丢了它下次重跑快速检查失效，整个目录会被判定为「全变」而全量重传 |
| `-l` | `--links` | 符号链接按链接原样复制。**不加它，遇到 symlink 会 `skipping non-regular file` 静默跳过**（`node_modules` 里遍地都是） |
| `-p` | `--perms` | 对齐权限位。不加时 rsync 更新已有文件的内容却**不动它的权限**，旧的 644 会一直留着，脚本可能 `Permission denied` |
|  | `--info=progress2` | 只显示**整体**进度（百分比、速度、剩余时间），每秒刷新一行，**不逐文件刷屏**。比 `--progress` 适合大目录 |
| `-n` | `--dry-run` | 只打印计划动作，不落盘。操作非空目标前必跑 |
| `-i` | `--itemize-changes` | 每个动作输出 `>f.st......` 形式的标记（见后文详解） |

短参顺序无所谓（`-rtlp` = `-r -t -l -p`）。非 root 本地不需要 `-o -g`，chown 只会失败并刷噪音。

> **唯一容易出错的地方**：源和目标都写 **`A/` `B/`（末尾带斜杠）**。少了斜杠，rsync 会把 `A` 目录本身塞进 `B`，结果是 `B/A/...` 而非把内容铺进 `B`。

---

## 场景

把 `A/` 合并进一个**已存在、非空**的 `B/`——同一块盘的不同文件夹，或另一块盘 / 移动硬盘。目标是**只补差异、不动已有的**。

---

## 末尾斜杠决定语义

```bash
rsync -av A B/     # → B/A/...   把 A 目录本身放进去
rsync -av A/ B/    # → B/xxx     把 A 的内容铺进 B
```

| 短参 | 长参 | 释义 |
|------|------|------|
| `-a` | `--archive` | 归档模式 = `-rtlp`（递归 + 软链接原样 + 权限 + 时间）+ `-ogD`（属组 / 属主 / 设备特殊文件），等价 `cp -a`。**带 `-o -g`，本地非 root 会产生 chown 失败噪音**，所以主力命令用 `-rtlp` 即可 |

目标不存在时两种写法结果一样，**一旦目标非空，差别致命**。合并永远写 `SRC/` `DST/`。

重跑一次就是增量——相同文件跳过，只补新的和改过的。

---

## 为什么比 cp -r / mv 快

`cp -r` **无脑重写整个目录**——10000 个文件里 9999 个一样，它也照样一个个复制。

rsync 默认的快速检查（quick check）只比对**文件大小 + 修改时间**，一致就跳过，**连文件内容都不打开读**。50 GB 目录做第二次合并，通常几秒结束。

「增量」不靠某个参数，而是 **rsync 的默认行为**；参数只是让它更快、更可控。

## 本地 vs 远程：走的是完全不同的代码路径

```bash
rsync -av A/ B/                    # 本地（A、B 都在本机）
rsync -av A/ user@host:/dst/       # 远程
```

| 短参 | 长参 | 释义 |
|------|------|------|
|  | `--whole-file` | 整文件读写。**本地传输默认已启用**；远程默认走 delta 传输（源端算 checksum、目标端算局部 checksum，只传不一样的块）。所以本地**不需要**加它，远程**建议**加 |

| 维度 | 本地 | 远程 |
|------|------|------|
| 传输方式 | whole-file 整文件读写 | 默认 delta 差异传输 |
| `-z`（压缩，已解释） | 无意义——数据不出机器，压缩纯浪费 CPU | 有意义，省带宽 |
| 字节级断点续传 | **不支持**（没有 delta 比对可复用） | 支持，`--partial` 有效 |
| 权限/属主 | 常见做法是直接砍掉（见下节） | 必须靠远端配合 |

## 跨盘还是不跨盘？rsync 根本不关心

rsync 只判断「本地 or 远程」，**不区分同盘 / 跨盘**，两者的参数完全一样。差异只在物理瓶颈：

| 情形 | 瓶颈 | 顺序大文件量级 |
|------|------|---------------|
| 同盘 → 同盘 | 读 + 写在同一块盘，走页缓存 | SATA SSD ~500 MB/s；NVMe ~2-6 GB/s |
| SATA SSD → 机械盘 | 机械盘顺序读写 | ~150-250 MB/s |
| SATA SSD → USB 3.x 移动硬盘 | 桥接芯片 + 机械盘 | ~80-150 MB/s |
| NVMe → NVMe（两块不同盘） | 两块盘并行 | 2-3 GB/s |

同盘复制的特点是**读一次 + 写一次落在同一块盘**，SSD 缓冲下能跑到读速的 2-3 倍；跨盘则被慢的那一块拖死。所以批量搬运前先确认瓶颈在谁身上，再决定要不要换工具。

### 真正的数量级飞跃：CoW clone（reflink）

支持块级 CoW 的文件系统（Btrfs、XFS reflink、ZFS、APFS、ReFS）上，"复制"不是复制数据，而是给同一份数据加一个新名字：

```bash
cp -a --reflink=always A/ B/     # Linux，coreutils ≥ 8.21
cp -c A/ B/                     # macOS（APFS clonefile）
```

`--reflink=auto` 在不支持的文件系统上自动退化成普通拷贝。**1 TB 目录瞬间完成，磁盘空间在首次写入时才真正产生。**

**rsync 做不到这件事**，它只会老老实实读写字节。所以同盘 + 支持 CoW + 文件不是立刻要改（写时复制的前提成立）时，`cp -a --reflink=always` 是唯一能快出一个数量级的方案。NTFS 不支持，Windows 上没这条路。

## 想更快：把 -a 拆开，只搬数据

主力命令已经砍掉了 `-o -g`（本地 chown 必失败）。还能再砍的是 `-p`：它带来的 chmod 开销只在**权限与目标不一致**时才发生，省下它的收益不大，但触发「移动后 `Permission denied`」的风险实在——所以只在两种情况下用下面的极简组合：

- 目标目录**全新**、或你确信两边权限已经一致 → 可以省掉 `-p`
- **纯数据搬运**（后续会重设权限、或只在 Windows 上用）→ 砍掉 `-p`、`-l`

```bash
rsync -rt A/ B/                                           # 最快：递归 + 保留 mtime
rsync -rtl A/ B/                                          # 目录里有符号链接时必须加 -l
rsync -rtL A/ B/                                          # 想把符号链接的内容当普通文件复制
rsync -rt --exclude='.git' --exclude='node_modules' A/ B/   # 排除无关目录
rsync -rtq A/ B/                                          # 安静模式，不刷屏
```

| 短参 | 长参 | 释义 |
|------|------|------|
| `-r` `-t` `-l` | `--recursive` `--times` `--links` | 已解释（见「30 秒上手」）。`-t` 必留，理由同上 |
| `-p` | `--perms` | 已解释。省掉它 = 接受「目标端已有文件权限不更新」的风险 |
| `-L` | `--copy-links` | 把符号链接**指向的内容**当普通文件复制，与 `-l` 互斥 |
| `-q` | `--quiet` | 不输出非错误信息。**大量小文件时终端输出本身就是瓶颈**，几万行打印比复制本身还慢 |
|  | `--exclude=PATTERN` | 排除匹配的路径 / 文件名。**收益最大的一项**——大部分慢在「拷了根本不需要的目录」 |
|  | `--filter=RULE` | 更强的规则（`+ ` 保留 / `- ` 排除 / `! ` 清除之前的规则），按序生效 |
| `-O` | `--omit-dir-times` | 不设置目录 mtime，省掉大量 utimes 调用，Windows / CIFS 上尤其明显 |
|  | `--omit-link-times` | 不设置符号链接的 mtime |
|  | `--sparse` | 稀疏文件保留空洞不写零。VM 镜像、特殊日志必备 |
| `-H` | `--hard-links` | 识别并保留硬链接（省空间）。会建内存索引，文件数极多时反而变慢，按需开 |

### 什么时候干脆别用 rsync

| 场景 | 更快的选择 |
|------|-----------|
| 同盘 + 支持 CoW 的文件系统 | `cp -a --reflink=always`（数量级差距） |
| Windows 跨盘大批量 | `robocopy /E /Z /J /MT:8`（原生多线程，见下节） |

## 断点续传（本地）

先说结论：**本地传输下 rsync 没有字节级断点续传**，因为本地是 whole-file 覆写，没有 delta 比对可以复用。有四种用法：

### 1. 重跑同一命令（推荐，天然「文件级续传」）

```bash
rsync -rt --info=progress2 A/ B/
```

| 短参 | 长参 | 释义 |
|------|------|------|
|  | `--partial` | 保留中断处的目标端临时文件。**本地意义有限**：文件下次仍会从头重传，只是别再删掉半成品 |
| `-P` | `--partial --progress` | 上一项 + 显示进度，远程场景的标配 |

中断后**重跑同一条命令**：quick check 会把已完成的文件全部跳过，只补没传完的。文件级「续传」就是这么实现的——代价是**单个大文件要从头再来**。

### 2. 单个大文件要续传 → --append

```bash
rsync -rt --append --info=progress2 big.iso /mnt/dst/
rsync -rt --append-verify --info=progress2 big.iso /mnt/dst/
```

| 短参 | 长参 | 释义 |
|------|------|------|
|  | `--append` | 只传目标端**缺失的尾部字节**，已有部分一个字节都不动。前提：目标端已有内容与源文件开头完全一致（下载中断的 ISO、大 tar 包、复制到一半的大文件）。**本地传输也生效** |
|  | `--append-verify` | 同上，但传完对**整个文件**做校验和；不匹配则清空重传。慢但安全 |

`--append` 不能与 `--inplace` 同用，也不适合「两边各有各自修改」的合并场景。

### 3. Windows 跨盘 → robocopy /Z

```powershell
robocopy D:\src E:\dst /E /Z /J /MT:8 /FFT /R:1 /W:1 /XD node_modules .git /LOG+:copy.log
```

| 参数 | 释义 |
|------|------|
| `/E` | 递归并包含空目录（合并语义，非镜像） |
| `/Z` | **可续传模式**，中断后重跑从断点继续 |
| `/J` | unbuffered I/O，大文件减少缓存拷贝；部分版本与 `/Z` 组合会报参数错误，报错就去掉其一 |
| `/MT:8` | 8 线程并发，小文件海量时比单线程 rsync 快数倍 |
| `/FFT` | 允许 2 秒精度的时间戳差异，**FAT32 / exFAT 移动硬盘必加** |
| `/R:1 /W:1` | 失败重试 1 次、间隔 1 秒，别用默认的 1000 次 × 30 秒 |
| `/XD` | 排除目录 |
| `/LOG+:` | 追加日志（`/LOG` 是覆盖） |
| `/MOVE` | 复制成功后删源，等价 `rsync --remove-source-files` |
| `/L` | 只列不复制，等价 `--dry-run` |

### 4. dd 手动续传（最底层）

```bash
# 目标已有 2048 MB：源和目标都跳过前 2048 个 1MB 块，且不清空目标原有内容
dd if=big.iso of=dst.iso bs=1M skip=2048 seek=2048 conv=notrunc status=progress
```

`conv=notrunc` 是关键（不清空目标）。仅在 rsync 版本不支持 `--append` 时用。

## 读懂 --itemize-changes 的输出

`-i`（已解释）会用**固定 11 字符**的标记列出每个动作。以 `>f.st......` 为例：

| 位置 | 字符 | 分组 | 说明 |
|------|------|------|------|
| 1 | `>` | 更新方向 | 见下表 |
| 2 | `f` | 文件类型 | 见下表 |
| 3 | `.` | 更新状态 | `+` 新建 · `c` 内容变了 · `.` 已存在 |
| 4-11 | `st......` | 属性标记 | 8 位，`.` = 一致，字母 = 有差异 |

### 第 1 位 · 更新方向

| 字符 | 含义 |
|------|------|
| `>` | 传给目标端（本地场景最常见） |
| `<` | 从目标端传回来 |
| `c` | 属性就地更新，不传数据 |
| `h` | 硬链接 |
| `.` | 未改动，跳过 |
| `*` | 消息行，后跟文字（如 `*deleting   old.txt`） |

### 第 2 位 · 文件类型

`f` 普通文件 · `d` 目录 · `L` 符号链接 · `D` 设备文件 · `S` socket 等

### 第 3 位 · 更新状态

| 字符 | 含义 |
|------|------|
| `+` | 新建——本次传输数据 |
| `c` | 内容变了——需要传输 |
| `.` | 已存在，无需传输数据 |

### 第 4-11 位 · 属性标记

`.` 表示与目标端一致，不用动；字母表示有差异：

| 字符 | 属性 | 有差异时的后果 |
|------|------|--------------|
| `s` | 文件大小 | **重传整个文件** |
| `t` | 修改时间 | **重传整个文件** |
| `p` | 权限 | 只改属性，不传数据 |
| `o` | 属主 | 只改属性 |
| `g` | 属组 | 只改属性 |
| `u` | 访问时间 | 只改属性 |

末尾两位是 ACL / 扩展属性，日常场景几乎总是 `.`。

> 新文件的 9 个状态位（位置 3-11）全为 `+`：`>f+++++++++`

### 对照示例

| 标记 | 拆解 | 含义 |
|------|------|------|
| `>f+++++++++` | `>` 传给目标 · `f` 文件 · `+` 新建 · 9 位全 `+` | 目标端**没有这个文件**，全量创建 |
| `>f.st......` | `.` 已存在 · `s` 大小不同 · `t` mtime 不同 | 已有文件**大小和时间变了** → 重新传输 |
| `.f...p.....` | `.` 未改动 · `p` 只有权限不同 | 不传数据，只改目标端权限 |

### 其他常见行

```text
cd+++++++++           创建目录
cL+++++++++           创建符号链接
>f..t......           只有 mtime 变了 → 照样全量重传（经典坑）
.f...p.....           只有权限变了 → 不传数据
*deleting   old.txt   只有配合 --delete 才会出现
```

### 让输出更干净

```bash
rsync -avni --out-format='%i %n%L' A/ B/
```

| 短参 | 长参 | 释义 |
|------|------|------|
|  | `--out-format=FMT` | 自定义每行输出格式，`%i` 标记 · `%n` 文件名 · `%L` 符号链接指向 |

`-v` 的文件名行和 `-i` 的标记行会混在一起，用它可以只留动作计划。

## 先 dry-run，再动手

```bash
rsync -avhn --itemize-changes A/ B/
```

| 短参 | 长参 | 释义 |
|------|------|------|
| `-h` `-n` `-i` | `--human-readable` `--dry-run` `--itemize-changes` | 已解释 |

**操作非空目标前先 dry-run**，逐行确认：

- 路径前缀正确（没有意外多出一层 `B/A/`）
- 动作类型（新建 / 覆盖 / 改属性 / 删除）符合预期
- 该被覆盖的文件确实是你打算覆盖的

## 输出控制：-v 与 --info=progress2

```bash
rsync -avh --info=progress2 A/ B/
```

| 短参 | 长参 | 释义 |
|------|------|------|
| `-v` | `--verbose` | **逐个文件**输出一行做了什么。信息量大但会刷屏，十万级文件的目录刷起来看不清当前在干什么 |
| `-h` | `--human-readable` | 人类可读单位（K/M/G）。配合 `-v`、`--info=progress2`、`--stats` 生效 |
|  | `--info=LEVEL2` | rsync 3.1.0+ 的新式信息控制。`LEVEL2` 即 `progress2`（已解释）：只显示整体传输进度，每秒刷新一行 |
|  | `--progress` | 老式总进度，会**逐文件刷屏**——大目录下不如 `--info=progress2` |
|  | `--stats` | 结尾打印一条汇总（传输了多少字节、加速比等），排查「到底有没有在传」很好用 |

选择建议：

| 场景 | 用什么 |
|------|--------|
| 文件数不多（几百个以内），想看清每个文件干了什么 | `-rtlpvh` |
| 文件数多 / 目录大，只关心整体进度 | `-rtlp --info=progress2`（主力命令默认） |
| 大目录 + 想保留断点续传 | 加 `-P`（`-P` = `--partial --progress`，见下表） |

## move：copy 完再删源

```bash
rsync -rtlp --info=progress2 --remove-source-files A/ B/
```

| 短参 | 长参 | 释义 |
|------|------|------|
|  | `--remove-source-files` | 传输成功后删掉对应的**源文件**，只留空目录树 |
|  | `--remove-empty-dirs` | 连空目录一起删（配合上一项才能真正释放磁盘） |

更可控的两步走（中途断了也不丢数据）：

```bash
rsync -avh --itemize-changes A/ B/                        # 1. 先全部补齐
# 确认 B/ 文件数量、大小对上之后：
find A -type f -delete && find A -type d -empty -delete   # 2. 再删源
```

- 传输成功后才删源文件，中途中断不丢失数据。

### 移动的安全实践

`--remove-source-files` 会**真删源文件**，命令写错就是数据没了。一次到位的本地参数组合：

```bash
rsync -rtlp --info=progress2 --remove-source-files A/ B/
```

| 短参 | 长参 | 释义 |
|------|------|------|
| `-l` `-p` | `--links` `--perms` | 已解释。本地 move **必须带上**：`-l` 防止符号链接被静默跳过，`-p` 防止目标端已有文件的权限与源不一致 |

短参顺序无所谓（`-rtlp` = `-r -t -l -p`）。`-o -g` 可以不要——本地非 root 时 chown 只会失败并刷噪音。

### 单源权威场景不要加 -u

`-u`（已解释）只看时间戳，与「源是权威」直接冲突：

- 目标端有一份内容过时、但被别的工具 touch 成新 mtime 的副本 → `-u` 保留目标数据、**拒绝用源覆盖**。
- 源端 mtime 被工具改旧（解包、checkout、部分同步软件）→ 同上，源明明更新却被跳过。
- 被 `-u` 跳过的文件**不会删源** → 源目录清不空，很容易诱发手工 `rm`，那才是真丢数据。

`-u` 的正确用途是**多机汇聚防倒退覆盖**，不是单源搬运。

### 两遍法（推荐的 move 姿势）

```bash
rsync -rtlp --info=progress2 -i A/ B/                    # 第 1 遍：只增量拷贝，不删任何东西
rsync -rtlcn --checksum A/ B/                            # 校验：无输出 = 目标已逐字节对齐
rsync -rtlp --info=progress2 --remove-source-files A/ B/   # 第 2 遍：几乎不传数据，只删源
```

| 短参 | 长参 | 释义 |
|------|------|------|
| `-i` `-n` `-c` | `--itemize-changes` `--dry-run` `--checksum` | 已解释 |

信心应该来自**「校验无差异」**，而不是来自 `-u`，更不是直接开 `--remove-source-files` 赌一把。任何一步发现源数据有问题，都只是白等一趟——**绝不会删掉一个没传成功的文件**。

### 上机前的护栏

| 检查 | 怎么查 | 为什么 |
|------|--------|------|
| 目标不在源内部 | `Resolve-Path A, B` | 目标若在源内部会**无限递归复制**直到爆盘，rsync 不会拦 |
| 路径没写反 | 确认 `A/` 是要搬走的、`B/` 是留下的 | 写反 = 把本该留下的数据删掉 |
| 没有漏的非普通文件 | `Get-ChildItem A -Recurse -Force | Where-Object LinkType` | 符号链接、socket 会被静默跳过（退出码还是 0） |

## 想更严格的校验

```bash
rsync -avhc A/ B/              # 算内容哈希逐字节比对（准确但慢）
rsync -avh --ignore-existing A/ B/       # 目标已存在的一律跳过（只补新文件）
rsync -avu B/ A/                        # 源比目标旧就跳过，防止倒退覆盖
rsync -avh --size-only A/ B/             # 只看大小，最快但可能漏
```

| 短参 | 长参 | 释义 |
|------|------|------|
| `-c` | `--checksum` | 跳过 size+mtime 快速检查，改为**比对内容校验和**。**唯一能发现「大小相同但内容被改过」的手段**。代价：源和目标**都要完整读一遍**再算哈希（默认 MD5，新版可用 `--checksum-choice=XXH64` 换更快的哈希），纯 IO + CPU 开销 |
|  | `--ignore-existing` | 目标端已存在的文件一律跳过，一个字节都不覆盖。只补新文件时用 |
| `-u` | `--update` | 源文件 mtime **比目标端更旧（或相同）时跳过**——防止旧数据覆盖新数据 |
|  | `--size-only` | 跳过 mtime 比对，只看文件大小，最快但会漏（mtime 被改过、内容确实变了时失效） |

### -u 的判断依据

`-u` 的「旧 / 新」判定，取决于**快速检查的结果**，因此会跟着其他参数变：

| 组合 | `-u` 实际在比什么 |
|------|------------------|
| `-au`（默认） | 比 mtime |
| `-au --size-only` | 比文件大小 |
| `-au --checksum` | 比内容校验和 |

典型用途：从备份 / 老机器往新目录同步时，防止陈旧文件把新文件覆盖回去。

### 移动前的对齐校验

`-c`（已解释）最实用的场合不是同步，而是**move 之前确认目标已和源逐字节一致**——`--remove-source-files` 是不可逆删除，先花一次读的时间换一份确定性：

```bash
rsync -rtlcn --checksum A/ B/                          # 只读校验，不写任何数据
rsync -rtlp --info=progress2 --remove-source-files A/ B/   # 确认无差异后再删源
```

| 短参 | 长参 | 释义 |
|------|------|------|
| `-n` `-r` `-t` `-l` `-p` | `--dry-run` `--recursive` `--times` `--links` `--perms` | 已解释 |

**没有任何输出就代表目标端与源逐字节一致**（有输出就是在列「准备更新的条目」）。之后第二遍几乎是 no-op，只负责删源。

## --delete：镜像同步（危险）

```bash
rsync -avh --delete A/ B/            # 让 B/ 与 A/ 完全一致
rsync -avhn --delete A/ B/          # 先看会删什么（强烈建议）
```

| 短参 | 长参 | 释义 |
|------|------|------|
|  | `--delete` | 删除目标端**多余**的文件/目录，让结果与源一致（默认不删，必须显式开） |

合并场景里 `--delete` 极易误伤，务必先 dry-run。

## 远程同步与断点续传

```bash
rsync -avh --info=progress2 -P src/ user@host:/data/dst/
```

| 短参 | 长参 | 释义 |
|------|------|------|
| `-P` | `--partial --progress` | 已解释：断点续传组合，远程场景的标配 |
| `-z` | `--compress` | 传输时压缩。**只对远程有意义**，本地加纯属浪费 CPU |

其他要点：

- **本地不需要** `--whole-file`：本地传输默认就是整文件读写；远程才需要它来绕过 delta 传输算法（见「本地 vs 远程」）。
- Windows 原生没有 rsync，用 Git Bash / MSYS2 / cwRSync / WSL。跨盘（D: → E:）属于本地传输，不走网络；要极致速度用 `robocopy /E /Z /J /MT:8`（见「断点续传」）。

## 踩坑速查

| 坑 | 现象 | 解法 |
|----|------|------|
| 忘记源目录末尾斜杠 | 多出一层 `B/A/` | 源和目标都写 `SRC/` `DST/` |
| 目标已有同名目录 | 源目录被塞进已有目录内部 | 先 dry-run 确认路径前缀 |
| 用 `--progress` 跑大目录 | 进度条刷屏刷到看不清 | 换 `--info=progress2` |
| 本地加 `-z` | CPU 飙升、速度反而降 | 本地去掉 `-z` |
| `--remove-source-files` 残留空目录 | 磁盘没释放 | 加 `--remove-empty-dirs` |
| 不敢操作非空目标 | 怕覆盖已有文件 | 先 dry-run 看计划 |
| mtime 被改过导致全量重传 | 同内容文件仍被复制 | `--checksum` 确认，或 `--ignore-existing` |
| 多机器同步被旧文件覆盖 | 老机器的数据盖掉新的 | 加 `-u`（`--update`） |
| 中断后重跑，单个大文件仍从头传 | 本地没有字节级续传 | `--append`（本地也生效），或改用 robocopy `/Z` |
| `rsync -rt` 静默跳过符号链接 | 报 `skipping non-regular file`，`node_modules` 里内容缺失 | 加 `-l`（保留链接本身）或 `-L`（复制链接内容） |
| 砍掉 `-a` 后每次都全量重传 | mtime 没保留，quick check 失效 | `-rt` 的 `-t` 必留 |
| 单源权威场景加了 `-u` | 目标端的旧数据被保留，源还删不掉 | 去掉 `-u`，改用两遍法 + `--checksum` 校验 |
| 移动后脚本 `Permission denied` | 目标已有文件是 644，rsync 更新内容时不动权限 | 加 `-p` 强制对齐（`-a` 同理） |
| 目标端有文件删不掉 | Windows 上文件被占用，`failed to remove`（数据已拷完） | 关掉占用它的程序，重跑同一命令继续删 |
