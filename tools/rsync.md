# rsync 速记

场景：把 `A/` 合并进一个已存在、非空的 `B/`（同盘、跨盘、移动硬盘都一样），只补差异、不动已有的。rsync 只分本地/远程，不关心同盘/跨盘。

## 主力命令

```bash
rsync -rtlp --info=progress2 A/ B/
```

- `-r` 递归
- `-t` 保留 mtime，**必留**。丢了它下次重跑快速检查失效，整个目录会被当成「全变」全量重传
- `-l` 符号链接原样复制。不加遇到 symlink 直接静默跳过，`node_modules` 里遍地都是
- `-p` 对齐权限位。不加的话 rsync 更新内容但不动目标端旧文件的权限，之后脚本可能 `Permission denied`
- `--info=progress2` 整体进度一行刷新，不逐文件刷屏

非 root 别带 `-o -g`，chown 只会失败刷噪音。

**动手前先 dry-run**：`rsync -rtlpni A/ B/`（`-n` 不落盘、`-i` 逐条列动作）。确认没有多出一层 `B/A/`、动作类型符合预期，再真跑。

## 末尾斜杠

`rsync A/ B/` 把内容铺进 B；`rsync A B/` 把 A 目录本身塞进去变成 `B/A/`。目标不存在时怎么写都一样，**一旦非空差别致命**。源和目标都带斜杠就对了。

## 为什么快

quick check 只比**大小 + mtime**，一致就跳过，内容根本不读。重跑一遍就是增量，50 GB 的目录第二次几秒结束。`cp -r` 是无脑全量重写。「增量」是默认行为，参数只是让它更快更可控。

## 想更快

- **排除无关目录收益最大**——大部分慢在拷了根本不需要的东西：`--exclude='.git' --exclude='node_modules'`
- **纯数据搬运**（不管权限/属主/时间戳）的最快形态：

```bash
rsync -r --inplace --no-whole-file A/ B/
```

  - `--inplace` 直接在目标文件上写差异块，省掉「临时文件 + 重命名」的写放大
  - `--no-whole-file` 本地默认整文件读写，加上它才走块级增量，只读写变化的块
  - 别加 `-z`（数据不出机器，压缩纯耗 CPU）、别加 `-c`（全盘读一遍算哈希）
  - **代价**：不带 `-t` 时快速检查退化成只比大小，同尺寸不同内容会被漏掉。只适合一次性搬运或内容不再变的数据；要反复跑就老实留着 `-t`
- 首次全新复制（目标不存在/全是新文件）：`rsync -rW --inplace A/ B/`。`-W` 整文件直拷，省掉滚动校验和的 CPU，比增量算法还快
- 海量小文件（数十万个）：加 `--no-inc-recursive`，先一次性建完整文件列表再传，过程更连贯
- `--info=progress2` 本身**不加速**。几十万小文件时终端刷新的开销可能比拷贝还大，想要极限速度就静默跑，另开终端 `watch df -h /dst` 或 iostat 看写入。单个大文件加不加无所谓

## 输出

- 文件少想看清每个动作：`-rtlpvh`（`-v` 逐文件、`-h` 人类可读单位）
- 目录大只关心进度：`--info=progress2`；老式的 `--progress` 会逐文件刷屏
- `--stats` 结尾汇总，排查「到底有没有在传」好用

`-i` 的 11 字符标记，日常就认这几种：

```text
>f+++++++++   目标没有，全量创建
>f.st......   大小/时间变了 → 整个重传
>f..t......   只有 mtime 变了 → 照样重传（经典坑）
.f...p.....   只有权限不同 → 不传数据，只改属性
*deleting     只有配合 --delete 才会出现
```

格式：1 方向（`>` 传过去 / `c` 只改属性 / `*` 消息行）· 2 类型（f 文件 / d 目录 / L 链接）· 3 状态（`+` 新建 / `c` 变了 / `.` 已有）· 后 8 位属性差异（s 大小、t 时间、p 权限、o 属主、g 属组）。s/t 有差异会重传整个文件，其余只改属性。

## move：传完再删源

```bash
rsync -rtlp --info=progress2 --remove-source-files A/ B/
```

传成功才删源，中途中断不丢数据。加 `--remove-empty-dirs` 连空目录一起清，不然磁盘不释放。`-l` `-p` 必须带全——防符号链接被跳过、防目标端旧文件权限不齐。

两个坑：

- **单源权威别加 `-u`**。它只看时间戳：目标端被别的工具 touch 成新 mtime 的旧副本会拒绝被覆盖，源还删不掉，很容易诱发手工 rm——那才是真丢数据。`-u` 是多机汇聚防倒退用的，不是搬运用的
- **删源不可逆，求稳走两遍**：先 `rsync -rtlcn --checksum A/ B/` 校验，**无输出 = 目标已逐字节对齐**，再跑上面那条删源。信心来自校验，不是赌一把

上机前确认目标不在源内部（`Resolve-Path A, B`），否则无限递归爆盘，rsync 不会拦。

## 校验

- `-c` 跳过快速检查，改比内容哈希。**唯一能发现「同大小但内容被改过」的手段**，代价是两边都要完整读一遍
- `--ignore-existing` 目标已存在的一律跳过，只补新文件
- `--size-only` 只比大小，最快但会漏

## 断点续传

本地没有字节级续传（whole-file 覆写，没有 delta 可复用）：

- 中断就**重跑同一条命令**，quick check 跳过已完成的，这就是「文件级续传」。代价是单个大文件从头再来
- 单个大文件续传用 `--append`：只补目标缺的尾部字节，前提是已有部分与源文件开头完全一致（下载中断的 ISO 这类）。本地也生效。更稳用 `--append-verify` 传完整个校验。注意不能和 `--inplace` 同用
- `--partial` 保留半成品临时文件，本地意义不大
- Windows 跨盘别折腾 rsync，直接 robocopy：

```powershell
robocopy D:\src E:\dst /E /Z /J /MT:8 /FFT /R:1 /W:1
```

  `/Z` 断点续传、`/MT:8` 八线程、`/FFT` 移动硬盘（FAT32/exFAT）必加、`/R:1 /W:1` 别用默认的重试 1000 次。部分版本 `/J` 和 `/Z` 冲突，报错去掉一个

## 远程

```bash
rsync -avhPz src/ user@host:/data/dst/
```

- 远程默认 delta 传输（只传不一样的块），本地默认整文件读写，两者代码路径完全不同
- `-z` 压缩**只对远程有意义**，本地加纯属浪费 CPU
- `-P` = `--partial --progress`，远程标配
- Windows 原生没 rsync，用 Git Bash / MSYS2 / WSL

## 什么时候别用 rsync

- 同盘 + Btrfs / XFS reflink / APFS / ZFS：`cp -a --reflink=always A/ B/`。CoW 是给数据加个新名字，1 TB 瞬间完成、写入时才真正占空间。rsync 只会老老实实读写字节。NTFS 没这条路
- Windows 大批量跨盘：robocopy 多线程原生更快

## 踩坑速查

| 坑 | 解法 |
|----|------|
| 少了末尾斜杠，多出一层 `B/A/` | 源和目标都写 `SRC/` `DST/` |
| 砍掉 `-a` 后每次全量重传 | `-t` 必留 |
| `rsync -rt` 静默丢符号链接 | 加 `-l`（保留链接本身）或 `-L`（复制链接内容） |
| 移动后脚本 `Permission denied` | 加 `-p` 对齐权限 |
| 本地加 `-z` 速度反降 | 去掉 `-z` |
| 大目录用 `--progress` 刷屏 | 换 `--info=progress2` |
| 海量小文件加进度反而更慢 | 静默跑，另开终端看 df |
| `--remove-source-files` 留一地空目录 | 加 `--remove-empty-dirs` |
| mtime 被改过导致全量重传 | `--checksum` 确认，或 `--ignore-existing` |
| 多机同步被旧文件盖掉新数据 | 加 `-u`（仅限这个场景） |
| 目标端文件删不掉（Windows 占用） | 关掉占用它的程序重跑，数据其实已经拷完了 |
